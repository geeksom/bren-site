# Bren — Ideal Customer Profile (ICP) and Fit Rules

> Used by sales, marketing and the on-site assistant to judge fit, steer to the right CTA, and be honest about poor fit.

## 1. Ideal customer profile

| Dimension | Ideal | Acceptable | Poor fit |
|---|---|---|---|
| Company size | 50–2,000 people | 15–50, 2,000–10,000 | <15 people; >10,000 (needs custom scoping — route to demo, do not decline) |
| Work type | Knowledge work: software, product, design, marketing, ops, consulting, professional services, digital health, edtech, fintech, logistics SaaS | Mixed (e.g. hardware companies with large software/ops teams) | Frontline-only workforces (retail floor, manufacturing line) with no desk tools |
| Work model | Remote or hybrid, multi-timezone | Co-located but multi-team | Single room, <10 people who talk all day |
| Chat | Slack or Microsoft Teams in daily use | Gmail/Outlook heavy, light chat | No shared chat tool |
| Project tool | Jira, Notion, Trello, Airtable, Monday or ClickUp in daily use | Tasks tracked in docs/spreadsheets (Bren tasks can substitute) | Asana / Linear / Basecamp only (roadmap — value reduced, still workable via chat+docs) |
| Structure | Defined teams and reporting lines; managers of 2–4 teams | Flat, but with project owners | No stable teams or owners |
| Pain | Status meetings, slow onboarding, leaders informed late, context loss | One of these | None acknowledged |
| Security posture | Cloud SaaS accepted with SOC 2 + DPA | Requires EU residency / SSO / SCIM (Enterprise) | On-prem only, no cloud allowed (we do not offer on-prem; VPC on Enterprise is the closest) |

## 2. Best-fit industries (with the angle)

- **Software / SaaS** — engineering managers running stand-ups; OKR culture; Jira + Slack + GitHub all connected.
- **Product-led startups (Series A–C)** — fast-changing projects, frequent re-planning, execs wanting momentum.
- **Consultancies / agencies / professional services** — many concurrent client projects; seniors interrupted by "quick questions"; onboarding onto client context.
- **Digital health / regulated SaaS** — value permission mirroring, SOC 2, private notes; often Enterprise for residency.
- **Logistics / marketplace SaaS with ops teams** — multi-timezone, leaders need momentum without meetings.
- **Edtech / non-profits** — price-sensitive; 20% nonprofit discount; Team plan.

## 3. Trigger events (when a prospect is most likely to buy)

- New VP/COO/Chief of Staff hired ("I need to understand what's happening").
- Headcount crossed ~50 or ~150 (rituals stop scaling).
- Going remote/hybrid or adding a second timezone.
- Reorg or new team structure.
- Complaints about meeting load; a "meeting-free day" initiative.
- Onboarding cohort incoming (hiring wave, acquisition).
- Quarterly planning / OKR reset.
- A leader or key person leaving (context loss scare).

## 4. Disqualifiers and how to handle them honestly

| Situation | What to say |
|---|---|
| <15 people | "Bren works from 1 seat, but pays off most from ~15 people, when staying informed starts costing meeting time. Start the free trial if you're hiring; otherwise you may not need us yet." |
| No project tool at all | "You can create lightweight tasks in Bren and still get digests, timeline and Ask Bren; most teams connect a project tool within a month." |
| Asana / Linear / Basecamp only | "Those are on the roadmap. Today you'd get chat, meetings, docs and GitHub — most of the value — and we'll notify you when your tool ships." Offer to record interest. |
| On-prem only | "We don't offer on-prem. Enterprise includes a private-VPC deployment in your cloud account and EU/US residency — if that meets your policy, book a demo with our security team." |
| Frontline-only workforce | "Bren is built for desk-based knowledge work; it won't help a workforce without chat/docs/tickets." |
| Wants employee monitoring | "Bren isn't a monitoring tool and we won't position it as one. It summarises updates people post and activity in shared work tools; no screens, keystrokes or app tracking." |
| Needs a language we don't fully support | "English is fully supported; Spanish, French, German and Portuguese are in beta. Other languages: Ask Bren will respond, but digests may be lower quality." |
| >10,000 people | "We have customers to ~1,400 seats today. For your size we'd scope a phased rollout — book a demo." |

## 5. Fit-scoring rubric (for the assistant / SDRs)

Score 0–2 on each; 8+ = strong fit, 5–7 = fit, <5 = be honest about limits.

1. Size 50–2,000 (2) / 15–50 or 2,000–10,000 (1) / other (0)
2. Slack or Teams daily (2) / email-centric (1) / none (0)
3. Supported project tool (2) / docs or spreadsheets (1) / unsupported tool only (1) / none (0)
4. Remote/hybrid or multi-team (2) / co-located multi-team (1) / one room (0)
5. Named pain: status meetings, onboarding, leaders informed late, context loss (2 if two or more, 1 if one, 0 if none)

## 6. Self-serve vs. sales-led (which CTA)

- **Start free trial (/signup/)** when: ≤100 people or a single department piloting; wants to try; no SSO/SCIM/residency requirement; no formal procurement.
- **Book a demo (/book-demo/)** when: 100+ seats or company-wide rollout; needs SSO/SCIM, data residency, VPC, custom retention, DPA/security questionnaire; wants pricing on invoice; multi-org (holding companies); needs a pilot plan or change-management help; is a consultancy rolling out across client teams.
- When in doubt: recommend the trial *and* offer the demo ("start the trial today; we can walk your leadership through a rollout plan in parallel").

## 7. Personas most likely to sign up vs. book a demo

| Persona | Typical path |
|---|---|
| Engineering/Product manager | Trial → Team plan for their teams → champions Business |
| Chief of Staff / Head of Ops | Demo → Business pilot on one department → company-wide |
| COO / CEO (50–300 people) | Demo or trial; Business |
| CISO / IT | Joins the demo; needs `06-security-compliance.md` |
| Founder (<50 people) | Trial → Team |
